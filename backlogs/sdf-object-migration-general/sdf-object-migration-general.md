## 対象読者と前提知識

| ロール | 活用シーン |
|--------|-----------|
| 開発者 | SDFでのcustomrecord/field/role/script/workflow等の環境間移行作業を担当する |
| コンサル | 移行プロジェクトの計画時に、実務で起こりうる落とし穴を事前に把握しておきたい |
| PM/管理者 | AIエージェント（Claude Code等）にSDF移行作業を任せる際、何を根拠に判断させているかを理解しておきたい |

前提として、SuiteCloud CLI (`suitecloud`) の基本操作（`object:import`/`project:deploy`等）と、SDFのプロジェクト構成（`Objects/`・`deploy.xml`・`manifest.xml`）を理解していることが望ましい。

---

## 概要

`skills/sdf-object-migration-general.md` は、NetSuiteのSDFプロジェクトで**ある環境（SB/QA等）から別の環境（本番等）へカスタムオブジェクトを移行する**作業を、AIエージェント（Claude Code等）に一貫した手順で実行させるためのスキルファイルである。

customrecord・customlist・field・role・center・script・workflow等、SDFで扱えるあらゆるカスタムオブジェクトの移行を対象とし、以下を1本のドキュメントにまとめている：

- 標準的な移行手順（対象確定 → 取得 → 差異確認 → デプロイ → 未解決対応 → 記録）
- 実務で繰り返し踏んできた落とし穴とその回避策（10カテゴリ・事例集）
- 判断に迷った際にAIが自走せず「一旦停止してユーザーに確認する」べき境界線

---

## 背景：なぜこのガイドが生まれたか

JKCプロジェクトでのSDF移行作業を重ねる中で、同種のエラーや判断ミス（依存関係の解決漏れ、内部ID直書きによる環境間の不整合、保存検索のエンコード起因の失敗等）が案件をまたいで繰り返し発生していた。

これらは一つ一つは些細でも、**都度ゼロから調査し直すとコストが大きく、AIエージェントに作業を任せる場合は特に「知らずに間違った判断をする」リスクが高い**。そこで、個別プロジェクトの実装詳細（特定の認証ID、日本語パス対応など）を除いた汎用部分だけを抽出し、どのSDFプロジェクトにも持ち込める形に切り出したのがこのガイドである。

## このガイドでカバーする範囲

スキルファイル本体（`skills/sdf-object-migration-general.md`）の構成は以下の通り：

| セクション | 内容 |
|-----------|------|
| 適用対象・前提 | どんな指示のときにこのガイドを使うか、認証・シェル選択の前提条件 |
| 手順①〜⑥ | 対象一覧作成 → 取得元確認・import → 差異検知時の一旦停止 → デプロイ → 未解決依存の洗い出し → 記録 |
| チェックリスト | 手順の実施漏れを防ぐためのチェック項目 |
| 既知の落とし穴（事例集） | 1. オブジェクト間の参照・依存関係／2. `object:import`特有の失敗パターン／3. 内部ID直書き問題／4. `deploy.xml`運用上の罠／5. デプロイ後のデータ起因エラー／6. コマンド使い分け／7. 運用上の教訓／8. カスタムレコードのデータ行移行／9. recid→scriptid特定／10. スキーマ上の既知制約 |
| Canonical References | Oracle公式ドキュメントへのリンク |

特に事例集の**内部ID直書き問題（3）**と**カスタムレコードのデータ行移行（8）**は、SDFの検証（`--dryrun`）が正常を返しても実際には不整合が起きうる、見落としやすい罠として重点的にまとめられている。

## 構成の読み方

このガイド最大の狙いは「AIが自走してよい範囲」と「必ず人間に確認を仰ぐべき境界」を明確に分けている点にある。

- 手順③「相違・懸念点があれば一旦停止する」に該当する状況（対象外のオブジェクトが実在する、標準レコードのデータ移行、列挙値の制約等）を検知したら、AIは後続処理を進めずユーザーに提示して指示を待つ。
- 逆に、`object:list`での実在確認や`--dryrun`検証など、副作用のない読み取り専用の調査は自走してよい。

この線引きにより、AIに移行作業を任せつつも「気づかないうちに間違った環境へ書き込む」「対象外のオブジェクトを巻き込む」といった事故を防ぐ設計になっている。

## 使い方：AIスキルとして導入する

Claude Code等のAIエージェントを使うSDFプロジェクトの `CLAUDE.md` に、以下のように登録して使う。

```markdown
## 必須スキル（SDFオブジェクト移行）

- 「〇〇を移行して」「SBから取得してデプロイして」等、SDF経由でのオブジェクト移行を指示された場合は、
  必ず `skills/sdf-object-migration-general.md` の手順・チェックリストに従うこと。
```

AIへの指示例：

```
customrecord_xxx をSB環境から本番環境へ移行してください。
skills/sdf-object-migration-general.md の手順に従い、
差異や懸念点を検知したら一旦停止して確認を取ってください。
```

## 別プロジェクトへ導入する際の注意

スキルファイル冒頭に明記されている通り、このガイドは特定プロジェクトの環境固有情報を含まない汎用版である。導入先では以下を読み替える：

- 「取得元環境」「デプロイ先環境」＝ 導入先プロジェクトの実際のauthid
- プロジェクトパスに日本語等ASCII外文字を含む場合、`object:import`/`file:import`がパス解決に失敗することがある（Windows上のSuiteCloud CLIで確認）。ASCIIパスの別プロジェクト（ミラープロジェクト）経由での書き込み運用が必要になるケースがあるが、これは環境依存の対応でありガイド本体の手順そのものではないため、導入先のパスに問題がなければ対応不要。
